emit::deltas::tests::non_provoking_vertex_values_reach_the_pixel_shader | ours | geometry shader: the pipeline's GS (made by victory-shader for flat vertex values #203) is refused by the front with E_NOTIMPL; needs MSC's GS emulation (docs/metal/m4-render.md, 'Geometry shaders')
emit::memory_tests::early_depth_stencil_skips_occluded_read_mark_pixel_shaders | ours | test bug that D3DMetal tolerates: the test calls SetGraphicsRootConstantBufferView(0 and 1) on parameters that Host::root_signature_for makes 32-bit constants; our back refuses a root descriptor on a constants parameter (INVALID_ARG, as the D3D12 debug layer does). With those two calls removed the test passes on ours (verified). Graphics/mesh draws themselves work
emit::rect::tests::rectangles_get_their_fourth_corner | ours | geometry shader: the pipeline's GS (made by victory-shader for flat vertex values #203) is refused by the front with E_NOTIMPL; needs MSC's GS emulation (docs/metal/m4-render.md, 'Geometry shaders')
emit::valu_tests::v_cvt_u16_and_i16_f16_saturate | ours | NaN handling of converted shaders: MSC 4.0 turns NaN/Inf optimization on by default (UserManual.md, 'NaN/Inf optimization'), so v_cvt_i16_f16(NaN) gives 0x8000 (console: 0). IRCompatibilityFlagDisableNanInfOptimization fixes it (verified on this test's DXIL through the back); not set globally: it is a performance/compile-time trade-off. D3DMetal passes
emit::valu_tests::v_sin_and_v_cos_f16_reduce_large_turns | ours | same root cause: v_sin_f16(NaN) gives 0 (console: NaN) with MSC 4.0's default NaN/Inf optimization; IRCompatibilityFlagDisableNanInfOptimization gives 0x7e00 (verified on this test's DXIL through the back); not set globally; D3DMetal passes
